1개요

외부 온라인 저지(BOJ 등)에 의존하지 않고, 로컬 문제 세트에 여러 풀이 코드를 동일 조건으로 실행해 정답 여부 + 실행 시간을 비교하는 학습용 도구.

무엇을 하나

하나의 문제(입력/기대출력 케이스 묶음)에 대해 Java .class/.jar 또는 Python 등 외부 실행 풀이를 같은 stdin/stdout 계약으로 돌려, 케이스별 통과 여부와 소수점 ms 단위 실행 시간을 측정·비교하고 콘솔·CSV·GUI로 리포팅한다.

설계 철학

책임 분리 + 확장점. 데이터가 한 방향으로 흐르는 파이프라인이고, 변경 가능성 높은 지점(Solution·OutputComparator·ResultLogger)은 인터페이스로 추상화 — 엔진 수정 없이 구현체만 추가하면 확장된다.

2아키텍처 — 5단계 파이프라인

로드 → 실행 → 비교 → 결과 수집 → 리포팅. 각 단계가 독립 패키지이며 한 방향으로만 의존한다.

그림 1. Main(CLI) 또는 AlgoBenchApp(GUI)이 이 파이프라인을 호출한다.

3패키지 맵

src/algobench/ 아래 7개 패키지. 색 막대 = 파이프라인 단계 대응.

domain/

불변 도메인 객체

  • Problem — 제목·제한·케이스
  • TestCase — 입력/기대출력

loader/

자체 텍스트 포맷 파싱

  • ProblemLoader — 헤더+### 케이스 파싱

solution/

핵심 다형성 지점

  • Solution (interface)
  • JavaJarSolution — 같은 JVM
  • ExternalProcessSolution — 외부 프로세스
  • ExecutionResult

compare/

채점 정책

  • OutputComparator (interface)
  • ExactOutputComparator
  • WhitespaceNormalizingComparator

engine/

비동기 채점 오케스트레이션

  • JudgeEngine — ExecutorService 풀
  • GradingTask — Callable<BenchmarkResult>

result/

불변 결과 + 리포팅

  • BenchmarkResult · TestCaseResult
  • Console/Csv/Composite ResultLogger
  • CsvResultFormatter · BenchmarkSummaryPrinter

gui/ 신규

Swing 프레젠테이션 (코어 무수정)

  • AlgoBenchApp · FlatTheme · FlatButton
  • ProblemList/Detail Panel
  • Submission(s)Panel · JavaSourceCompiler
  • ResultsPanel · BenchmarkRunner

Main

CLI 진입점 / 데모 러너

  • 인자 파싱 → 풀이 생성 → 채점 → 비교 요약

6Solution 다형성 — 두 실행 전략

동일한 stdin → stdout 계약을 두 구현체가 서로 다른 방식으로 만족한다.

왜 직렬화? System.in/out은 JVM 전역. Java 풀이를 병렬로 돌리면 출력이 섞이므로 스트림 교체 구간을 static 락으로 직렬화. 병렬성은 외부 프로세스 풀이에서 확보.
GUI 격리 선택 — 에디터에 적은 Java는 컴파일 후 java -cp tmp Class 외부 프로세스로 실행해, 사용자 코드의 System.exit()·무한루프가 GUI JVM을 죽이지 못하게 한다.

7채점 실행 흐름

GUI는 EDT를 절대 막지 않는다 — 빌드·채점은 SwingWorker 백그라운드, UI 갱신만 EDT.

그림 3. 풀이별 빌드 실패는 격리되어 해당 탭에만 표시되고, 나머지 채점은 계속 진행(NFR-04).

8Swing GUI 계층

백준식 워크플로 — 문제 선택 → 소스 작성/첨부 → 채점 → 결과 비교. 순수 Swing(외부 LAF 없음), 코어 무수정.

입력 3가지 유형

  • Java 에디터 — 작성 → javax.tools in-process 컴파일 → 외부 java 격리 실행
  • 파일 첨부 — .java(컴파일) / .class·.jar(JavaJarSolution 직접 로드)
  • 외부 명령 — python "sol.py" 등 임의 실행 명령

컴포넌트 데이터 흐름

ProblemListPanel → 콜백 → ProblemDetailPanel. SubmissionsPanel이 EDT에서 스냅샷(Spec)을 떠 BenchmarkRunner가 백그라운드에서 빌드·채점 → ResultsPanel이 표시. 모든 스타일은 FlatTheme 한 곳.

9문제 파일 포맷

KEY: VALUE 헤더 + ### 케이스 구분 + INPUT:/EXPECTED: 블록. UTF-8.

예시 — problems/a_plus_b.txt

TITLE: A+B
TIME_LIMIT_MS: 2000
MEMORY_LIMIT_MB: 256
###
INPUT:
1 2
EXPECTED:
3
###
INPUT:
-3 10
EXPECTED:
7
# … 케이스 반복

파싱 규칙

요소의미
TITLE문제 제목 (필수)
TIME_LIMIT_MS케이스별 시간 제한(ms, 강제)
MEMORY_LIMIT_MB메타데이터 전용 — 강제 안 함
###케이스 구분(한 줄 전체)
INPUT:stdin 주입 블록
EXPECTED:기대 출력 블록 (INPUT 뒤)
\r\n·\r → \n 정규화, 케이스별 후행 개행 trim. 중복 키는 오류.

10판정 우선순위

GradingTask가 케이스마다 적용하는 순서. 위에서 먼저 걸리면 해당 판정으로 확정.

PASS

정답 + 시간 내

FAIL

오답 / 런타임 에러

TIMEOUT

제한 초과 (강제 종료)

11빌드 · 실행 (빌드 도구 없음)

javac/java 직접. build.ps1 또는 algobench.bat이 단계를 묶는다.

컴파일 + 실행

# 엔진 + GUI 컴파일 → out/
javac -encoding UTF-8 -d out (src/**/*.java)

# 샘플 Java 풀이 → out_solutions/
javac -encoding UTF-8 -d out_solutions (solutions/java/*.java)

# CLI 채점
java -cp out algobench.Main problems/a_plus_b.txt \
     out_solutions/CorrectSolution.class \
     "python solutions/python/correct_solution.py"

GUI 실행

# 컴파일 후 Swing GUI
.\build.ps1 -Gui

# 또는 직접
java -cp out algobench.gui.AlgoBenchApp

# 또는 대화식 콘솔 메뉴 [7]
.\algobench.bat
2단계 컴파일 — 엔진은 out/, 풀이 .class는 out_solutions/. 런타임에 JavaJarSolution이 URLClassLoader로 풀이 클래스를 로드한다.

12핵심 제약 · 비기능 요구

절대 제약

  • 순수 Java SE만 — Maven/Gradle 없음, 런타임 외부 의존성 0
  • 테스트 프레임워크 없음 — Main 데모 러너 end-to-end 검증
  • 네트워크·DB·웹 UI·계정 관리 전부 범위 밖
  • 메모리 제한은 메타데이터로만 보관 (강제 안 함)

비기능 요구 (NFR)

NFR-03엔진 수정 없이 구현체 추가(확장점 3 인터페이스)
NFR-04예외 격리 — 케이스 단위 catch, 계속 진행
NFR-05병렬 채점 무간섭 — 불변 + 방어적 복사, 순차 로깅
NFR-06사람이 읽기 좋은 콘솔 출력
불변성 원칙 — 모든 도메인/결과 객체는 생성자 주입 + getter, 컬렉션은 List.copyOf 방어적 복사. 공유 가변 상태 없음 → 병렬 채점 중 결과가 섞이지 않는다.
