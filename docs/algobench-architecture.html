AlgoBench · 인터페이스 사양 → 실행 로직 & 구조

로드.실행.비교.수집.리포팅

로컬 알고리즘 벤치마킹 엔진. 여러 풀이 코드를 동일 조건으로 실행해 정답 여부 + 실행 시간을 비교한다. 변경 가능성 높은 지점은 전부 인터페이스로 추상화 — 엔진 수정 없이 구현체만 갈아끼운다(NFR-03). 이 문서는 소스의 실제 시그니처에서 추출한 실행 구조도.

순수 Java SE 빌드 도구 0 · 런타임 의존성 0 stand-alone · 단일 머신 병렬 채점 · ExecutorService

03

실행 시퀀스 — JudgeEngine.evaluateAll

제출은 병렬, 수집·로깅은 메인 스레드에서 제출 순서대로 순차. 결과가 섞이지 않는다(NFR-05).

① 문제 로드 & 풀이 빌드

ProblemLoader.loadProblem → Problem. 인자별로 .class/.jar → JavaJarSolution, 그 외 → ExternalProcessSolution. 동명 풀이는 name#2로 유일화.

② 비동기 제출 — evaluateAllAsync

풀이마다 new GradingTask(problem, solution, comparator)를 threadPool.submit(). List<Future<BenchmarkResult>>를 제출 순서로 반환(블로킹 없음).

③ GradingTask.call() — 케이스 루프

각 TestCase마다 solution.execute(input, timeLimit) → judge() → TestCaseResult. 총 실행시간 누적. 케이스 단위 예외 격리(NFR-04): 한 케이스가 터져도 errorMessage에 기록하고 다음으로 진행.

④ 결과 수집 + 순차 로깅

메인 스레드가 Future를 순서대로 f.get() → 즉시 logger.log(result). 병렬 채점이지만 로깅은 단일 스레드 직렬화. ExecutionException은 방어적으로만(정상 경로엔 안 옴).

⑤ 비교 요약 + 셧다운

BenchmarkSummaryPrinter.printComparison으로 풀이 간 비교(G1). shutdown() → awaitTermination(2s) → 미종료 시 shutdownNow()로 지연 task 회수, JVM 종료 막지 않음(G4).

05

동시성 & 스레드 안전

병렬 이득은 외부 프로세스에서. JVM 전역 스트림 충돌은 락으로 직렬화. 데이터는 전부 불변.

JavaJarSolution SERIALIZED

System.in/out/err는 JVM 전역. 스트림을 교체해 출력을 캡처하므로, Java 풀이를 동시에 돌리면 출력이 섞인다.

→ 스트림 스왑 구간을 static STREAM_LOCK으로 감싸 직렬화. per-call URLClassLoader로 static 상태 누수도 차단.

ExternalProcessSolution PARALLEL

자체 OS 프로세스라 완전 병렬. stdout/stderr는 별도 reader 스레드 2개로 동시 판독(데드락 방지).

타임아웃: waitFor(timeout) 초과 시 손자 프로세스까지 destroyForcibly()로 확실히 종료.

타임아웃의 비대칭

외부 프로세스 — 확실히 kill 가능.

Java 풀이 — 같은 JVM이라 강제 종료 불가. 데몬 스레드 + Future.get(timeout) best-effort. 타임아웃 표시는 하되 데몬이라 메인 종료를 막지 않는다(한계 명시).

불변 + 방어적 복사

모든 도메인·결과 객체는 final 필드 + getter. 컬렉션은 List.copyOf.

공유 가변 상태 없음 → 병렬 채점 중 결과가 섞이지 않는다(NFR-05). 로깅만 메인 스레드 순차.

06

진입점 — 같은 코어, 두 표면

CLI와 GUI 모두 동일한 ProblemLoader · Solution · JudgeEngine 코어를 호출한다. 표현 계층만 다르다.

CLI · 데모 러너

algobench.Main

java -cp out algobench.Main <problemFile> <solution...>
  1. 인자 확장자로 Solution 타입 판별
  2. CompositeResultLogger = 콘솔 + CSV
  3. evaluateAll → 비교 요약 → shutdown
  4. -Dalgobench.verbose=true로 케이스 상세
GUI · Swing

algobench.gui.AlgoBenchApp

java -cp out algobench.gui.AlgoBenchApp
  1. 문제 선택 → 소스 작성/첨부 → 채점 ▶
  2. BenchmarkRunner extends SwingWorker
  3. 빌드·채점은 백그라운드, 결과 콜백은 EDT
  4. 풀이별 빌드 실패 격리 — 나머지는 계속(NFR-04)

  • List caseResults

  • int testCaseIndex
